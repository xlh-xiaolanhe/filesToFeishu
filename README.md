# PDF / 公众号文章 → 飞书知识库

本地网页工具：批量导入文字型 PDF 或微信公众号文章，逐篇预览、校对确认后，保存为指定飞书知识库父页面下的独立子文档。PDF 附原文件，公众号附离线网页 ZIP。

当前版本：**v0.6.0**。本版修复审查发现的内容身份、并发编辑、发布恢复与历史性能问题。支持每批最多 20 个 PDF 或 20 个文章链接、持久化串行队列、逐篇核对后批量发布、一键环境准备和启动，以及可选的飞书机器人结果通知。

本 README 是持续维护的完整使用说明。`docs/` 仅保留本地需求、计划、架构和验收档案，不进入 Git；新检出项目无需这些文档即可使用。开发约定见 [AGENTS.md](AGENTS.md)，组件许可见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 一键启动

支持 macOS，Python 3.12 由 uv 按项目要求准备。先安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)；已安装 Homebrew 的用户可执行 `brew install uv`。然后在项目目录运行：

```sh
./start.sh
```

也可以在访达中双击 [start.command](start.command)。两者使用同一个 [启动脚本](start.sh)，从任意工作目录启动都可以。

脚本先检查是否已有服务运行，空闲时依次同步锁定依赖、在不存在时创建 `.env`、下载缺失的 Chromium 和 PDF 模型，再启动服务并自动打开 <http://127.0.0.1:8765>。首次准备需要联网，可能持续数分钟；失败时显示错误，修复后再次运行即可。已有 `.env`、任务和模型会保留，不覆盖凭证。飞书凭证需按下一节手工填写一次；未配置时仍可获取、转换与预览。

| 启动方式 | 适用情况 |
| --- | --- |
| `./start.sh` 或双击 `start.command` | 完整准备 PDF 和公众号功能，更新代码后也用此方式同步依赖 |
| `./start.sh --wechat-only` | 只准备公众号所需依赖和浏览器，跳过 PDF 模型；之后要用 PDF，先停止服务再运行默认命令 |
| `./start.sh --no-setup` | 环境已准备好，跳过依赖同步和所有下载，直接启动；更新代码后应先用默认命令 |
| `./start.sh --no-open` | 正常准备、启动，但不自动打开浏览器；可与其他参数组合 |
| `./start.sh --help` | 查看脚本参数 |

服务只监听本机，保持单进程、单后台线程。保留终端窗口，按 `Ctrl+C` 停止；修改 `.env` 后需重启。同版本、同数据目录已经运行时直接打开已有服务；其他服务或旧版本占用 8765 时会提示先停止，不自动杀进程。

希望手工准备环境时也可执行：

```sh
uv sync --extra parser --locked
.venv/bin/python scripts/download_models.py
.venv/bin/python -m playwright install chromium
test -f .env || cp .env.example .env
./start.sh --no-setup
```

## 飞书配置

编辑项目根目录的 `.env`，真实 Secret 只保存在本地，不发到聊天、日志或 Git：

```dotenv
FEISHU_APP_ID=你的企业自建应用AppID
FEISHU_APP_SECRET=你的企业自建应用AppSecret
FEISHU_PARENT_URL=https://公司.feishu.cn/wiki/父节点标识
DATA_DIR=.data
DOCLING_ARTIFACTS_PATH=.models
```

`FEISHU_PARENT_URL` 保留为兼容配置；网页不再自动回填，请在“知识库父页面链接”中填写本次目标。目标需是飞书知识库 `/wiki/` 父页面链接；工具在其下面创建子文档，不向已有文档追加正文。

需要配置两层权限：

| 位置 | 要求 |
| --- | --- |
| 飞书开发者后台 | 开通新版文档创建、编辑、读取，素材上传、下载，以及知识库读写接口权限；发布应用并完成管理员审批 |
| 目标知识库及父页面 | 把同一个应用或机器人加入可编辑成员，允许创建或迁入子页面 |

个人账号能编辑并不代表应用有权限。“检查保存位置”成功只说明能读取节点，仍需知识库编辑权限才能归档。凭证只发送给飞书接口，不发送到公众号站点。

## 飞书机器人结果通知

通知默认关闭。启用后复用 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 对应的企业自建应用，以应用机器人身份给一个指定用户或群发送结果。当前实现为单向通知，不接收聊天命令，不需要公网回调或长连接，也不使用群自定义机器人 Webhook。

1. 在飞书开发者后台为同一应用启用机器人能力，并开通 `im:message:send_as_bot`（以应用的身份发消息），发布应用并完成所需审批。
2. 私聊接收人需在应用可用范围内，使用该应用对应的用户 `open_id`；也支持 `user_id`、`union_id`、`email`。向群发送时，把机器人加入目标群，使用群 `chat_id`。ID 类型必须与值匹配，知识库节点 ID 不能作为接收人 ID。
3. 在本地 `.env` 填写以下配置，然后停止并重新运行启动脚本：

```dotenv
FEISHU_NOTIFY_ENABLED=true
FEISHU_NOTIFY_RECEIVE_ID_TYPE=open_id
FEISHU_NOTIFY_RECEIVE_ID=ou_替换为接收人的真实ID
```

群通知改为 `FEISHU_NOTIFY_RECEIVE_ID_TYPE=chat_id`，接收 ID 填 `oc_...`。接收人配置保存在本地，不返回到网页。接口格式参见飞书官方的[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)和[Python SDK 请求模型](https://github.com/larksuite/oapi-sdk-python/blob/v2_main/lark_oapi/api/im/v1/model/create_message_request_body.py)。

- **成功通知**：仅在飞书正文、素材、原件及知识库位置全部核验完成后发送，包含文档标题、任务 ID、批次 ID（如有）和文档链接。本地转换完成、等待预览确认时不发送成功通知。
- **失败通知**：已接收任务的转换或发布失败、写入结果不确定时发送简要提醒；详细错误仍在本机页面查看。取消、等待人工验证和尚未创建任务的输入校验错误不通知。不会发送正文、原件、凭证或原始异常日志。
- 批量任务逐篇通知，每篇仍生成独立文档；同一任务同一种结果只创建一条通知记录，反复核验或重试发布不会重复提醒。失败后最终成功会有一条新的成功通知。启用配置或重启不会追补历史任务。
- 任务队列和预览上方分别显示通知状态。“已发送”表示飞书接口已确认接收消息，不代表用户已读。通知失败不改变文档处理结果，也不阻断后续任务。
- 明确被拒绝的发送可以点击“仅重试通知”，不会重新转换或创建文档。修复权限后可直接重试；修改本地配置需重启。已确定的接收人及应用身份不能随重试改变，避免把旧通知发送到其他人。
- 发送超时、响应不完整或发送中服务中断时标为“发送结果待核对”，不盲目重复发送。发送前中断的记录可在重启后手工重试。重试不会依赖飞书消息去重的时效来假定安全。

本功能的配置与收发链路可用模拟飞书测试验证；真实发送需要有效接收人、机器人能力及消息权限。新配置建议先用一篇测试文档验证收到的链接和接收人，再处理批量任务。

## 批量使用流程

1. 选择来源。PDF 可一次多选文件；公众号链接每行一条。每批 1–20 项，链接输入中的完全重复行只提交一次。两种来源分别提交，均进入同一个队列。
2. 点击“开始本地转换”或“获取文章并预览”。按输入顺序逐项提交和处理，每项生成独立任务。单个上传或转换失败会明确显示，其余项继续；不会把多个来源拼成一份文档。
3. 在“任务队列”中查看批次与每项进度，点击“打开”逐篇核对。填写统一的“知识库父页面链接”，点击“检查保存位置”。每篇的标题可以分别修改。
4. 核对原文、转换结果及黄色缺项提示；修改代码后先点代码块内“保存”。再逐篇勾选“我已核对原文、代码片段及全部转换提示，确认正文和图片完整”。未核对、未保存代码或尚未转换完成的项目不会进入批量发布。
5. 点击“保存本批已确认任务”，将已确认项目逐项加入发布队列。也可对当前任务点击“保存到飞书”。各篇依次写入、回读并归档，只有显示“已保存”才算成功，可从列表打开各篇飞书文档。

确认绑定服务器上的内容版本、代码、素材摘要、标题、目标父页面和应用身份。PDF 和公众号都必须确认；缺失或过期凭证不能直接调用发布接口。确认记录在当前浏览器页面内有效；切换任务会保留已确认状态和填写的标题，刷新后需重新确认。修改代码、标题或目标会使相关确认失效；其他窗口改了内容时，发布会拒绝旧预览，需重新打开核对。

最多允许 50 个处于排队或处理中的任务。转换、发布使用同一串行队列；公众号等待人工验证时暂停后续处理，完成验证或取消后继续。尚未开始转换的任务可以打开后“取消排队”。关闭浏览器不会取消服务器已接收的任务；提交过程中关闭页面则尚未发送的项目不会自动补交，请检查队列后单独提交缺项。

重启不会自动重放未完成的转换或发布。已完成转换仍可预览；中断的转换需重新上传或获取；中断的发布从原任务核对后重试。不要删除任务或反复新建来绕开不确定的写入结果。

## 历史任务与输入记录

任务队列每页最多显示 50 项摘要，通过“较新任务 / 更早任务”翻页；批次筛选作用于当前页。每项右侧提供“删除”，确认后从队列、最近任务及对应批次中移除；删除当前打开的任务会同时关闭预览。全部删除后队列隐藏。

这是本地历史列表的逻辑删除：已生成的飞书文档不变，原件、素材及发布核验记录仍保留，供相同内容再次导入时回读核验、防止重复创建；不会释放这些文件的磁盘空间。正在排队、处理、等待验证或发送通知的任务不可删除；已有未完成核验的飞书写入需先在原任务中核对并完成发布，保留恢复入口。

链接、标题输入框关闭自动完成，本项目不再向浏览器保存这些填写记录。刷新或重新打开网页后，标题、文章链接、目标链接为空，不自动打开上次任务或选择上次批次；旧版保存的本项目回填记录会自动移除。手动点击“打开”历史任务时，仍展示该任务的标题及已锁定的发布位置，便于核对。任务历史本身继续保存在本机服务器中。浏览器自行保存的表单建议是否显示由浏览器决定，本项目不清除浏览器的全局历史。

## PDF 转换

每个 PDF 最大 20 MB、100 页，需有文字层。扫描件、加密或损坏文件不支持。PDF 解析在本机离线运行；只有确认发布后才上传到飞书。

预览按页对照原 PDF 和转换结果，普通文字、标题、列表、简单表格尽量可编辑；公式、复杂区域和覆盖不足的页面保留为图片并提示。原文件附在飞书文档末尾。可识别的独立页号、重复列表黑点会清理，数字键帽等装饰序号尽量转为基本数字；原件及左侧对照图仍保留原貌。标题结合字号、章节编号与上下文恢复层级，结构线索不足时仍需人工核对。

### 代码校对

- 代码文字优先提取，截图使用 macOS Vision 本地 OCR；保留换行、缩进及示例本身的错误，不执行或生成式补写代码。
- 预览只展示一个可编辑代码块；可选 JavaScript、TypeScript 或纯文本，按 Tab 插入两个空格。“查看原代码区域”默认折叠，供对照使用。
- OCR 代码需逐字核对中文、引号、括号、运算符、大小写、缩进和漏行，点块内“保存”后才能发布。修改时可“撤销”当前段未保存的内容；保存一段不会丢掉其他段的草稿。刷新会丢失未保存的草稿。
- 未识别的代码图片可点击“这是代码图片：改为代码片段”，手工录入并保存。单段最多 20000 字符。
- 相邻页代码具备可靠位置和语法接续证据时保守合并，需核对连接处后保存；不同示例、语言冲突、复杂字符串等保持分开。普通段落和表格的跨页重组暂不支持。
- 飞书中保存为原生可编辑代码块，局部参考图不重复上传为该代码块的图片。进入发布队列后内容锁定，避免与写入记录不一致。

升级不会自动改写历史任务或已发布文档；要应用新的识别规则，重新上传 PDF。相同文件、相同转换内容、相同应用及目标的已核验结果会复用；内容不同则创建新文档。

## 微信公众号文章

输入 `https://mp.weixin.qq.com/s/...` 公开文章链接，每行一篇。优先直接获取；遇到验证时打开项目独立的 Chromium 窗口。在窗口里完成验证，回网页打开对应任务并点击“继续获取”，也可“取消获取”。窗口使用临时会话，不读取个人浏览器配置，不保存登录凭证，不依赖 Codex 浏览器插件。

连续预览保留正文、标题、阅读顺序、普通表格、代码、链接、基础富文本、引用及嵌套列表；元信息缺失时不猜测。图片下载后上传飞书，GIF 保留原文件。未知代码语言使用纯文本，代码缩进保留；编辑后需保存。

音视频、小程序卡片等无法完整转换的部分，会保留能取得的标题、封面或原文入口，并在预览列出缺项；缺图不会静默遗漏。勾选确认代表你已审阅这些限制，不代表缺失内容已经完整转换。验证、删除、付费或不可访问页面不会被当成正文发布。字体、间距允许不同，不承诺逐像素一致；不提供订阅、自动更新或绕过访问限制。

每篇文档末尾附离线网页 ZIP，包含安全 HTML 副本、已获取的图片和缺项清单；解压后打开 `article.html`。脚本及危险事件被去除，不包含无法获取的媒体。原文链接保留用于追溯。相同规范化链接、正文、素材、转换结果、标题、应用和目标的已核验结果复用；修改内容、标题或目标会新建文档。公众号重复获取时 ZIP 捕获时间等打包元数据可能不同，语义内容及图片摘要相同时复用首次已核验的远端附件，并记录其实际摘要。

默认获取限制：HTML 8 MB、单素材 20 MB、累计素材 100 MB、单请求 30 秒；最终 ZIP 须不超过 20 MB，否则在发布前停止。可在 `.env` 调整 `WECHAT_MAX_HTML_BYTES`、`WECHAT_MAX_ASSET_BYTES`、`WECHAT_MAX_TOTAL_BYTES`、`WECHAT_TIMEOUT`；调整抓取上限不会改变飞书附件上限。获取只允许经过校验的公开 HTTPS 地址，拒绝内网地址及不安全重定向。

## 状态与故障处理

| 状态或提示 | 含义与操作 |
| --- | --- |
| 排队 / 等待发布 | 等待前面的任务完成；等待发布的内容已锁定 |
| 解析中 / 获取文章中 | 正在转换或获取当前来源 |
| 等待验证 | 队列暂停，打开该任务完成验证并继续，或取消该项 |
| 待确认 | 逐篇预览、保存代码校对，勾选确认后再发布 |
| 发布中 / 核验中 / 归档中 | 正在写入、回读正文和素材附件、迁入目标并核对实际位置 |
| 已保存 | 必需步骤均核验完成，点击结果链接打开 |
| 失败 / 待核对 | 查看该项错误；有预览和写入记录的任务可核对后重试，未完成转换的需重新上传或获取 |
| 找不到 uv / 首次准备失败 | 安装 uv 并检查网络，重新运行 `./start.sh`；已准备环境可使用 `--no-setup` |
| 8765 被占用 / 旧版本运行 | 在原服务终端按 Ctrl+C 停止后启动，不要同时启动多个实例 |
| 模型未准备 | 运行默认启动脚本；仅公众号模式不含 PDF 准备 |
| 鉴权失败 / `99991672` | 检查 App ID、Secret、应用发布状态及接口权限，审批后重启 |
| `131006` / 正文已写但归档失败 | 补齐知识库成员和父页面编辑权限，在原任务“核对状态并重试” |
| 响应丢失 / 写入结果不确定 | 原任务重试会先回读；不能确认的步骤继续停止，不盲目重复追加或创建 |
| 限流 | 程序有限退避重试；仍失败时稍后重试原任务 |
| 远端内容或位置已改变 | 核验停止以避免误复用；先检查远端，不要直接重复导入 |

单项失败不会阻止队列中其他任务。恢复依赖完整的 `.data`，不要只删数据库、检查点或原件。程序不会自动删除远端半成品。文档创建或素材上传响应丢失时，任务显示“候选文档 ID / 候选素材令牌”：在飞书找到候选对象后填写并点击“核验并关联”，系统只读核验应用归属、标题、空白文档或占位块归属及素材摘要。核验通过仍需重新勾选确认，在原任务续接到全文与目标核验完成；不是手工把状态改成成功。候选文档核验需当前应用机器人信息及文档元数据读取权限，缺权限时显示错误并保留未知状态。无法提供可靠候选时保持待核对，新建相同发布意图任务会被拦住并提示原任务 ID。已经开始的发布不能换标题、目标或应用身份。

## 数据保存与备份

| 路径 | 内容 |
| --- | --- |
| `.env` | 凭证、默认目标和目录配置 |
| `.models/` | PDF 本地模型 |
| `.data/jobs.sqlite3` | 原子保存的预览、内容摘要及版本；任务摘要、发布快照与逐键检查点分表保存 |
| `.data/jobs/<任务ID>/source.pdf` 或 `source.zip` | 各任务的原件 |
| `.data/jobs/<任务ID>/parsed.json` | 旧版内容文件，首次读取时兼容导入数据库；之后不再作为内容真源 |
| `.data/jobs/<任务ID>/assets/` | 图片、PDF 对照页和代码参考图 |

升级前先停止旧服务并备份整个 `.data`。启动时在持有实例锁的条件下事务迁移旧数据库，不自动重放任务；旧检查点键不变。内容编辑与摘要、版本同事务提交，中断时一并回滚。

代码编辑使用版本检查：另一窗口已保存时返回冲突并保留本窗口草稿。点击“加载最新版本对比（保留草稿）”，比较服务器版本后再保存，避免静默覆盖。

这些文件及 `.venv/`、`docs/`、生成产物均不进 Git。备份前停止服务，再备份整个 `.data` 和本地配置；不要把任务恢复数据当作可随意删除的缓存。本地清理不会删除飞书文档。

## 开发与验证

修改项目前先阅读 [项目 Agent 规则](AGENTS.md)，其中约定模块边界、格式扩展、Python 规范和交付要求。

自动门禁在 `.github/workflows/quality.yml`：Linux/macOS 快速测试、Ruff、mypy、提交空白检查及隔离浏览器回归，汇总为 `quality-gate`。模型/OCR 在独立手动工作流中验证，不依赖飞书凭证；真实飞书验收不在 CI 自动运行。

统一入口：`.venv/bin/python scripts/check_ci.py fast`、`browser` 或 `models`。browser 需要可用的 Node Playwright 和 Chrome（可配置 `NODE_PATH`）；models 需要 macOS Vision 和本地模型。显式完整验证若跳过测试将失败。工作流推送到 GitHub 后才有远端运行记录；仓库管理员需将 `quality-gate` 设置为 main 分支必需状态检查。仅添加工作流文件不会启用分支保护。

在已准备依赖的项目根目录执行：

```sh
# 快速测试：排除需要真实模型和 Vision 的测试
.venv/bin/pytest -m 'not parser and not live'
# 完整本地测试：需要 .models 和 macOS Vision，不向飞书写入
RUN_PARSER_TESTS=1 RUN_OCR_TESTS=1 .venv/bin/pytest -q
.venv/bin/ruff check src tests scripts
.venv/bin/mypy
# 独立验证浏览器真实交互测试（已安装 Google Chrome，不用个人配置）
RUN_BROWSER_TESTS=1 .venv/bin/pytest -q tests/converters/wechat/test_browser.py
.venv/bin/python -m tests.converters.pdf.samples
```

最后一条生成原创代表性样本 `output/samples/representative.pdf`，不包含用户数据。真实 Docling 测试禁止网络连接；飞书接口和任务测试使用模拟服务。若 Vision 在受限沙箱中不能运行，在本机终端执行完整测试。文档检查包含在 pytest 中：始终核对 README 使用说明、版本、链接和页面确认文案；存在本地 docs 时再额外检查归档一致性，新检出环境也可以独立验证。

浏览器自动化另需 Node.js、`playwright` 包和 Chrome；必要时用 `NODE_PATH` 指向现有 Playwright 包。先生成上述样本，选择下表一个模式启动 8766 测试服务，再在另一个终端运行对应脚本；切换模式前停止前一个测试服务。

| 验证内容 | 启动隔离服务 | 执行验证 |
| --- | --- | --- |
| 真实 PDF 转换与模拟发布 | `.venv/bin/python -m tests.browser_server` | `node tests/browser_smoke.cjs` |
| 多窗口编辑冲突与确认失效 | `TEST_CODE_PREVIEW=1 .venv/bin/python -m tests.browser_server` | `node tests/browser_review_smoke.cjs` |
| 代码编辑与跨页来源 | `TEST_CODE_PREVIEW=1 .venv/bin/python -m tests.browser_server` | `node tests/browser_code_smoke.cjs` |
| 批量输入与发布交互 | `TEST_BATCH_PREVIEW=1 .venv/bin/python -m tests.browser_server` | `node tests/browser_batch_smoke.cjs` |
| 公众号前端完整交互 | 无需启动项目服务，测试自行创建临时静态服务并模拟 API | `node tests/browser_wechat_smoke.cjs` |
| 历史删除、输入框不回填与多窗口同步 | 无需启动项目服务，模拟 API 与原创任务 | `node tests/browser_history_smoke.cjs` |
| 机器人通知状态与独立重试 | 无需启动项目服务，测试自行创建临时静态服务并模拟 API | `node tests/browser_notifications_smoke.cjs` |
| 标题层级预览 | `TEST_HEADING_PREVIEW=1 .venv/bin/python -m tests.browser_server` | 上传样本，确认文档标题/章节/小节/代码示例为 H1/H2/H3/H4，下一节恢复 H3，确认后模拟发布成功 |

这些模式使用临时数据库和模拟飞书；退出测试服务后临时任务会消失，截图保存在 `output/playwright/`。只有明确要创建真实验收文档时才执行 `RUN_LIVE_TESTS=1 node tests/browser_smoke.cjs`，它会连接 8765 正常服务并写入本地配置的真实父页面；失败任务应在网页历史中续接。

历次验收保留在本地 `docs/`；开源组件与模型许可见 [第三方说明](THIRD_PARTY.md)。
